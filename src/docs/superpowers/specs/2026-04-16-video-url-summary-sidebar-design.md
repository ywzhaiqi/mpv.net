# 视频 URL 摘要侧栏设计

## 目标

当播放器加载视频 URL，例如 `https://pan2.871015.xyz/d/a/b/c.mp4` 时，自动尝试读取同目录 `summary/` 下的：

- `c.md`
- `c_bd.md`

若任一摘要存在，则在播放器主窗口右侧显示摘要侧栏。若两者都存在，则上下排列显示两份摘要。摘要内容使用基础 Markdown 渲染，并将 `00:10`、`01:23:45` 这类时间文本识别为可点击项；点击后调用播放器 seek 到对应绝对时间。

若两份摘要都不存在，则不显示右侧栏。

## 范围

本次仅处理：

- 网络视频 URL
- 可配置单个摘要域名
- 基础 Markdown 渲染：标题、段落、列表、代码块、普通链接
- 时间文本识别与点击 seek

本次不处理：

- 本地文件摘要自动发现
- 富文本 Markdown 特性，如表格、图片、HTML 内嵌
- 摘要编辑、手动刷新、缓存持久化

## 用户体验

### 设置项

新增一个文本设置 `summary-host`，默认值为 `pan2.871015.xyz`。

- 当设置为空时，整个摘要自动加载功能禁用
- 当设置非空时，只有当前视频 URL 的 host 与该设置值完全匹配时，才会发起摘要请求
- 本次只支持单个精确域名，不支持通配符和多域名列表

### 触发时机

当播放器载入新媒体后，只有满足以下条件才异步发起摘要探测与加载：

1. 当前媒体路径是视频 URL
2. URL 的 host 与 `summary-host` 完全匹配

不满足上述条件时，不请求摘要，也不显示右侧栏。

### 右侧栏显示规则

- 只有至少一份摘要成功加载时才显示右侧栏
- 若 `c.md` 存在，则显示在上方
- 若 `c_bd.md` 存在，则显示在下方
- 若两者都不存在，则隐藏右侧栏

### 时间跳转

- 识别 `mm:ss` 与 `hh:mm:ss`
- 点击时间文本后，执行绝对 seek，避免相对跳转误差
- 不额外弹窗，不打断播放

## 摘要定位规则

给定媒体 URL：

`https://pan2.871015.xyz/d/a/b/c.mp4`

推导出：

- `https://pan2.871015.xyz/d/a/b/summary/c.md`
- `https://pan2.871015.xyz/d/a/b/summary/c_bd.md`

规则如下：

1. 保留原 URL 的 scheme、host、端口、目录
2. 从原文件名中取不带扩展名的基础名，例如 `c`
3. 在原目录下拼接 `summary/`
4. 生成 `<basename>.md` 与 `<basename>_bd.md`

仅当原 URL 看起来是视频资源且 host 与 `summary-host` 完全匹配时才执行该逻辑。视频判定优先基于扩展名，覆盖常见格式如 `mp4`、`mkv`、`webm`、`mov`、`avi`、`ts`。

## 不存在判定

摘要请求返回以下任一情况时，视为该文件不存在：

- HTTP 404
- 成功返回 JSON，但语义为对象不存在

其中 JSON 不存在判定以解析结果为准，要求满足以下特征：

- `code == 500`
- `message` 包含 `object not found`

示例：

```json
{"code":500,"message":"failed link: failed to get file: object not found","data":null}
```

除上述情况外，网络错误、超时、无效内容均按“该摘要不可用”处理，不提示用户，不影响播放。

## 架构设计

### 1. 摘要解析与加载服务

新增一个与 UI 解耦的摘要服务层，职责包括：

- 判断当前媒体是否为目标视频 URL
- 判断 URL host 是否匹配 `summary-host`
- 推导摘要 URL
- 异步请求摘要内容
- 判断“文件不存在”响应
- 返回可渲染的摘要结果模型

该层不直接依赖 WinForms 控件，便于测试。

### 2. Markdown 渲染模型

新增轻量解析层，将原始 Markdown 转成 WinForms 可消费的片段模型。模型至少支持：

- 标题
- 普通段落
- 列表项
- 代码块
- 普通链接
- 时间链接片段

时间识别在文本片段层完成，这样 UI 无需自己扫描字符串。

### 3. 主窗体右侧栏

在 `MainForm` 中新增右侧摘要容器，整体布局调整为：

- 左侧：mpv 播放区域
- 右侧：摘要侧栏

右侧栏默认隐藏。加载到摘要后显示固定宽度侧栏；同时存在两份摘要时，侧栏内部上下分区，并使用整个右侧栏的单一滚动容器，避免双滚动条。

### 4. seek 集成

点击时间片段后，由主窗体调用现有播放器命令接口，执行：

- `seek <seconds> absolute exact`

这样复用现有 mpv 命令通道，不额外引入播放控制抽象。

## 数据流

1. 播放器载入新文件
2. 主窗体读取当前媒体路径
3. 若是视频 URL 且 host 匹配 `summary-host`，则启动摘要加载任务
4. 服务层推导两个摘要 URL 并发请求
5. 服务层将成功结果转成摘要视图模型
6. 主窗体确认返回结果仍对应当前播放项
7. 有摘要则显示右侧栏；无摘要则隐藏
8. 用户点击时间片段，主窗体调用 seek

## 并发与生命周期

- 每次切换媒体时取消上一次摘要加载任务
- 异步结果回填前必须校验当前播放 URL 是否仍与请求发起时一致
- 旧请求结果不得覆盖新媒体的摘要状态
- 窗体关闭时释放未完成请求与相关资源

## 错误处理

- 摘要请求失败：静默忽略，视为不可用
- 摘要内容为空：视为不可用
- Markdown 解析失败：该摘要不显示
- 时间格式非法：按普通文本显示，不可点击

该功能不能影响以下已有行为：

- 正常播放
- 原有窗口尺寸调整
- 原有菜单和拖放
- 原有 mpv 输入与鼠标交互

## 测试策略

优先覆盖纯逻辑测试，避免把测试耦合到 WinForms 控件：

1. 视频 URL 判定
2. `summary-host` 精确匹配判定
3. 摘要 URL 推导
4. “object not found” JSON 判定
5. 时间文本解析为秒数
6. 文本片段中时间链接的提取
7. 两份摘要存在/不存在组合下的视图模型输出
8. 取消与过期结果保护

UI 层只保留少量集成验证，重点保证：

- 有摘要时侧栏显示
- 无摘要时侧栏隐藏
- 点击时间片段后发出正确 seek 命令

## 实施边界

实现时应尽量把新增代码拆成小单元：

- URL 与响应判定逻辑
- 设置读取与 host 匹配逻辑
- Markdown 片段化逻辑
- 主窗体绑定与展示逻辑

避免把网络请求、Markdown 解析、WinForms 控件拼接和 seek 命令全部塞进 `MainForm`。

现有 extension 机制适合承载播放器事件监听与独立逻辑，但没有主窗口右侧宿主 UI 扩展点。因此本次应将摘要加载与解析逻辑设计为可复用服务，同时把右侧侧栏集成放在主程序中实现，而不是放进 extension。

## 验收标准

- `summary-host` 默认值为 `pan2.871015.xyz`
- 当 `summary-host` 为空时，不请求摘要且不显示右侧栏
- 只有视频 URL 的 host 与 `summary-host` 完全匹配时，才自动请求同目录 `summary/` 下的 `c.md` 与 `c_bd.md`
- 返回“不存在”语义时，视为缺失，不报错
- 至少一份摘要存在时，右侧栏出现
- 两份摘要都存在时，按上下顺序显示
- 两份摘要都不存在时，右侧栏不显示
- 摘要中的 `mm:ss`、`hh:mm:ss` 可点击
- 点击后播放器跳转到对应绝对时间
- 切换播放项时不会出现旧摘要串到新视频上的情况
